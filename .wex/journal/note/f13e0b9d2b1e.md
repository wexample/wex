# Cause dossier wex-6 fantôme : config JetBrains (complète todo 427b2437a8ad)

Written: 2026-08-28
Author: agent:main

Complète le todo `427b2437a8ad` (Dossier wex-6 réapparaît après suppression) : la cause a été identifiée et corrigée.

Le dossier `WEX/local/wex-6` (et le fichier vide `.wex/bin/app-manager` qu'il contient) n'était pas recréé par un script wex ou un volume monté, mais par l'IDE JetBrains. Plusieurs fichiers de config dans `WEX/.idea/` (`WEX.iml`, `pySourceRootDetection.xml`, `workspace.xml`) et dans `PACKAGES/PYTHON/pip.iml` référençaient encore un ancien SDK Python nommé `Python 3.12 (wex-6)`, pointant vers `local/wex-6/.venv`, ainsi qu'un source root sur `local/wex-6/src`. Quand l'IDE indexe ces source folders configurés, il recrée le dossier vide.

Correction : remplacer ces références par le SDK du nouvel environnement, `Python 3.12 (WEX)`, qui pointe vers `local/wex/.venv/bin/python` (même venv, autre nom dans IntelliJ 2026.1 — il n'apparaît donc pas évident dans les settings).

Piège rencontré : `workspace.xml` est réécrit par l'IDE tant qu'il reste ouvert — les modifications doivent être appliquées IDE fermé, sinon il réinjecte les entrées `wex-6` (VCS branch, recent files, source root option) à la fermeture. Une fois corrigé IDE fermé puis rouvert, le dossier `wex-6` n'a plus été recréé après suppression + redémarrage (confirmé par l'utilisateur).
