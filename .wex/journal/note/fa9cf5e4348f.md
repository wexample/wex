# Préférence : uniformité via Registry à performance égale

Written: 2026-08-27
Author: agent:main

Pour l'implémentation de l'async sur les imports d'addons (et plus généralement pour tout ce qui touche au pattern Registry/RegistryContainerMixin, cf. roadmap `registrification.md`), la préférence explicite de l'opérateur est : "à performance égale, je préfère une version uniforme qui passe par le registre".

Contexte : deux approches distinctes existaient pour paralléliser les imports d'addons — (A) faire les imports en parallèle directement dans `wex.py:exec()` (approche initiale de `async.md` phase 1.5), ou (B) déplacer la résolution des classes dans le Registry (ex. `register_addon_modules([...])` avec support async). Ce n'est pas un détail visible dans le code actuel : c'est un critère de décision à appliquer lors de tout futur choix d'implémentation entre les deux — préférer B si le coût de performance de A vs B est comparable, pour ne pas avoir deux mécanismes différents résolvant le même problème (registrification vs ad-hoc).
