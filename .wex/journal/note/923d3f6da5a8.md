# Import lazy de black sûr uniquement car prepare() tourne avant le pool parallèle

Written: 2026-08-27
Author: agent:main

Dans le mixin batch de filestate (utilisé par `wex app::state/rectify`), le formatter black fait un import lazy (à l'intérieur de la fonction, pas en haut du fichier) pour éviter de charger black inutilement.

Ce lazy import a causé une race condition en mode async : plusieurs threads du pool parallèle tentaient d'importer black en même temps, provoquant des crashs/freezes.

La correction retenue n'a pas été de supprimer le lazy import, mais de s'appuyer sur le fait que `dry_run()` appelle désormais `_prepare_options()` (le `prepare()` du mixin batch) **en thread principal, avant** le lancement du pool parallèle. Résultat : black est importé une seule fois en main thread pendant `prepare()`, donc la race sur l'import ne peut plus se produire — sans qu'il soit nécessaire de retirer le lazy import.

Constraint à connaître : ceci dépend de l'ordre `prepare()` (synchrone, main thread) → pool parallèle. Si `prepare()` est un jour lui-même parallélisé ou déplacé après le lancement du pool, la race d'import sur black (et tout autre import lazy similaire) réapparaîtra. Ce n'est pas visible en lisant seulement le code du formatter black.
