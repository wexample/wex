# IoManager.log() non thread-safe (source des "trous" et crashs silencieux en async)

Written: 2026-08-27
Author: agent:main

Pendant le debug de `wex app::state/rectify --dry-run` en parallèle (32 workers), deux symptômes récurrents et non déterministes :
- des "trous" visuels dans le log (une ligne vide entre deux items numérotés consécutifs, sans gap dans la numérotation)
- des arrêts nets du process, à un item différent à chaque run, sans aucune trace d'exception (ni stack Python, ni signal capturé par faulthandler/atexit)

Test décisif : en forçant `max_workers=1`, zéro trou observé sur plusieurs runs, alors qu'il y en avait systématiquement au moins un en multi-workers.

Cause identifiée : les workers appelaient `self.log()` (IoManager) chacun depuis leur propre thread. L'IoManager n'a pas été conçu pour être appelé concurremment par plusieurs threads — cela produit un output "garbled" (les trous) et corrompt potentiellement un état interne, ce qui expliquerait les crashs silencieux.

Fix appliqué : les workers ne font plus aucun log/IO ; ils retournent juste leur résultat. Un seul thread (le thread principal) écrit dans l'IoManager, au fil des `as_completed()` sur les futures. Effet secondaire positif : le compteur `[N/total]` reflète maintenant l'ordre des complétions et non celui des démarrages, donc reste cohérent avec ce qui s'affiche.

À retenir pour tout code async futur dans wex : ne jamais logger directement depuis un worker thread ; centraliser l'IO de log dans le thread orchestrateur.
