# PDF Generator (SYRTIS) : démos en échec, cause probable $APP_PROJECT_NAME

Written: 2026-08-27
Author: agent:main

Ceci concerne le projet SYRTIS, module `project/utilities/pdf-generator` (paquet `syrtis_pdf_generator`), pas `wex` lui-même — travail encore à faire, à re-filer dans le journal SYRTIS.

Durant la session, un renommage incomplet du module Python `pdf_generator` → `syrtis_pdf_generator` a été corrigé (imports dans `http_server.py`, `__main__.py`, et `generate_demos.yml`, plus un sed en masse sur le reste du codebase pour les occurrences restantes). Le nom du conteneur Docker `pdf_generator` a été laissé tel quel intentionnellement — ce n'est pas un module Python, ça n'avait pas à changer.

Après ces corrections, `wex .pdf/generate-demos` échoue toujours : les 13 démos passent en FAIL. Le script bash qui orchestre les jobs masque les erreurs réelles (`SHELL_COMMAND_FAILED` générique sans détail). En lançant un job directement dans le conteneur, il tourne correctement — le problème vient donc du script d'orchestration, pas du code du générateur PDF.

Piste identifiée en fin de session : la variable `$APP_PROJECT_NAME` semble ne pas être définie dans le contexte où tourne le script, ce qui fait que `CONTAINER="${APP_PROJECT_NAME}_pdf_generator"` résout en `_pdf_generator` au lieu du vrai nom `pdf-generator_local_pdf_generator`. La session s'est arrêtée juste avant de vérifier cette hypothèse — reste à confirmer si `$APP_PROJECT_NAME` est bien vide dans ce contexte d'exécution et, si oui, corriger le script pour obtenir le nom de conteneur correctement (ou le rendre robuste à une variable absente).
