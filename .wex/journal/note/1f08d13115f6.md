# apply_operations reste séquentiel en mode interactif

Written: 2026-08-28
Author: agent:main

Contrainte de design sur `apply_operations` (filestate, Phase 1.1 — parallélisation déjà commitée) : quand `interactive=True`, l'exécution reste volontairement séquentielle plutôt que parallélisée.

Raison : en mode interactif, chaque opération peut demander une confirmation à l'utilisateur (op par op). Si on parallélisait, plusieurs confirmations se présenteraient en même temps de façon concurrente, ce qui casse le flux de confirmation. Le séquentiel n'est donc pas un oubli mais une contrainte UX délibérée.

À l'inverse, `build_operations` (inspection, lecture seule FS) n'a pas ce problème puisqu'il n'y a pas de confirmation utilisateur dans sa signature actuelle — il peut être parallélisé sans réserve sur ce point (le reste de son design, flatten-then-pool, est déjà couvert par le todo/note existant sur `build_operations`).
