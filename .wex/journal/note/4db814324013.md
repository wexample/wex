# Pas de cache pour le parsing config/workdir au démarrage

Written: 2026-08-27
Author: agent:main

Lors du profiling de `wex hi` (~220ms dans `_init_workdir`), la lecture/parsing YAML pesait ~90ms et le reste (imports lazy, scan d'options, `set_value`) le reste. L'idée d'un cache disque (hash des fichiers contributeurs pour invalider) a été étudiée puis **rejetée volontairement**.

Raison : pour être fiable, un tel cache doit hasher *tous* les `.py` des packages qui contribuent à l'arbre de config (option classes, providers, AddonManager, workdir custom) + l'état pertinent (env, version wex) — "soit on hashe tout, soit on ne le fait pas, l'entre-deux est interdit". Le risque d'invalidation incomplète (cache stale silencieux) coûterait potentiellement plus cher en debug (30-40 min perdues) que le gain visé (~130ms sur une CLI, pas un calcul de plusieurs secondes).

Décision explicite : accepter les 130ms plutôt que ce risque. Si quelqu'un reconsidère un cache ici, relire cette raison avant de s'y remettre — l'absence de cache dans le code ne l'explique pas.
