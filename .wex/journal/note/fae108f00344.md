# Répartition doc wex/addons : règles et description via pyproject.toml

Written: 2026-08-27
Author: agent:main

Décision d'architecture sur la répartition de la documentation entre `wex` (le noyau) et les addons, et sur comment `wex` obtient la liste des addons disponibles pour son README.

**Règles retenues :**
1. La doc vit où vit le code : un addon documente ses commandes, sa config, ses workdirs ; `wex` documente ce qui est vrai quel que soit le jeu d'addons (installation, boot, résolution de commandes, conventions). Remonter du contenu d'addon dans `wex` recrée la dérive de doc qui vient d'être nettoyée.
2. Le sens descendant (« pour installer le noyau, voir wex ») passe par le `package-readme/` de la suite, écrit une seule fois au niveau suite et propagé en cascade sur les 4 niveaux — pas de répétition manuelle.
3. **`wex` ne lit jamais le `.wex/knowledge/` des addons.** Le seul endroit où l'info addon est nécessaire côté wex est le rendu de son propre README, pour la section « addons disponibles » (nom + description + lien).

**Pourquoi pas le knowledge des addons :** lire `.wex/knowledge/` d'un addon depuis wex ne fonctionne pas en installation réelle. Le wheel d'un addon n'embarque que son `src/` (ex. `[[tool.pdm.build.packages]] include = "wexample_wex_addon_ai", from = "src"`), et `.wex/knowledge/` est à la racine du dépôt, hors de `src/` — donc absent du package une fois installé depuis PyPI (`bin/install` vide le venv et tire tout depuis PyPI). Ça ne marche qu'en local parce que les addons y sont en editable install.

**Solution retenue :** `importlib.metadata.metadata("wexample-wex-addon-xxx")["Summary"]` — fonctionne aussi bien en editable qu'en wheel PyPI, car la metadata est écrite dans le `.dist-info` au build. La description vient donc du `Summary` du `pyproject.toml` de chaque addon.

**Implémenté :** une méthode `addons()` (accessible depuis le kernel / config value) lit les dépendances `wexample-wex-addon-*` du `pyproject.toml` de wex et récupère le `Summary` de leurs métadonnées installées. Le tableau résultant est exposé via une nouvelle section knowledge `usage/addons.md.j2`, incluse dans le composer de contenu du README.
