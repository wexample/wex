# AppMiddleware et COMMAND_TYPE_APP sont orthogonaux

Written: 2026-08-27
Author: agent:main

Dans les commandes d'app (fichiers `.wex/commands/**/*.py`), le paramètre `app_workdir` n'est injecté que si la commande porte `@middleware(middleware=AppMiddleware)`. Une commande peut être `type=COMMAND_TYPE_APP` sans avoir ce middleware — ce n'est pas un oubli automatique, c'est un cas valide.

Les deux mécanismes sont orthogonaux :
- `COMMAND_TYPE_APP` gère le *routing/enregistrement* : "cette commande appartient au namespace d'une app".
- `AppMiddleware` gère l'*injection de dépendance* : "je veux le workdir de l'app injecté dans ma fonction".

Ils ne se déduisent pas l'un de l'autre. Une commande `COMMAND_TYPE_APP` sans middleware est légitime si elle n'a pas besoin du workdir (paramètres purs, logique indépendante de la config de l'app).

Conséquence pratique : si une commande d'app plante avec `TypeError: ... missing 1 required positional argument: 'app_workdir'`, la cause est l'absence de `@middleware(middleware=AppMiddleware)` sur la commande — pas un problème de signature générale à corriger partout. Ne pas ajouter ce middleware par réflexe à toutes les commandes d'app existantes sans vérifier qu'elles en ont réellement besoin (le cas historique était `bdo-letters/.wex/commands/install/update_deps.py`, corrigé en ajoutant le décorateur manquant).
