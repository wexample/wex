# AGENTS.md cible : structure conditionnelle selon accès wex

Written: 2026-08-27
Author: agent:main

Décision de conception sur le contenu que doit avoir `AGENTS.md` (actuellement une chaîne Python en dur dans `with_ai_workdir_mixin.py:22`, identique partout).

Diagnostic du problème actuel, dans les mots de l'opérateur : le fichier dit en substance « débrouillez-vous avec `wex talk` (qui n'est pas accessible aux agents en fait, mais aux users), et sinon allez chercher dans `knowledge` (qui est en `.md.j2`, alors qu'on a pour ambition de faire une version buildée) ». Les deux issues proposées mènent donc à un mur pour un agent sans accès à `wex`.

Structure cible proposée :
- Si l'agent a accès à `wex` : utiliser les commandes de consultation spécialisées du knowledge — `wex app::knowledge/read|search|explore` — ou l'exploration des sources — `wex app::sources/search|grep`.
- Si l'agent n'a pas `wex` : une version `.md` buildée et commitée du knowledge doit exister (le `.md.j2` brut n'est lisible par personne sans le moteur de rendu).
- Dans tous les cas : l'agent peut explorer librement le repo.

Conséquence retenue : sans `wex`, `.wex/knowledge/` en `.md.j2` n'est lisible par personne — il faut un rendu `.md` commité pour que cette branche fonctionne. C'est désormais tracé comme prérequis avant la réécriture d'`AGENTS.md` (phase 6 avant ce chantier), avec les noms de commandes ci-dessus. Le composer `_content.md.j2` (mécanisme du README, un seul fichier gouverne les 37 dépôts via cascade Jinja) est le modèle de référence pour rendre `AGENTS.md` dynamique plus tard — non prioritaire, le contenu minimal actuel n'est pas gênant en soi.
