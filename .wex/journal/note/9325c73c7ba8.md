# ThreadPoolExecutor : shutdown(wait=True) bloque Ctrl+C

Written: 2026-08-27
Author: agent:main

Constaté en debuggant le parallélisme de `rectify --dry-run` : utiliser `with ThreadPoolExecutor(...) as executor:` fait que `__exit__` appelle `shutdown(wait=True)`. Résultat : un `KeyboardInterrupt` ne peut pas interrompre proprement — il faut Ctrl+C plusieurs fois (5 dans le cas observé) et la stack trace remonte très lentement.

Correctif testé et retenu pour ce cas : remplacer le `with` par un `try/finally` qui appelle `executor.shutdown(cancel_futures=True)` — annule immédiatement les tâches encore en file et n'attend que les workers déjà lancés. À réutiliser pour tout futur usage de `ThreadPoolExecutor` dans wex (roadmap async), sinon même symptôme garanti sur Ctrl+C.
