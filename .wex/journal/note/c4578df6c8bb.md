# Suppression get_shortcut — complète le todo 4200529472fa

Written: 2026-08-27
Author: agent:main

Complète le todo existant `4200529472fa` (Supprimer get_shortcut (registre workdir)) avec le détail de l'audit fait en session et la décision de chemin prise :

**Raison du retrait** : `get_shortcut` permet de pointer un fichier dans l'arbre par un nom court, mais dans une suite plusieurs workdirs peuvent utiliser le même shortcut, ce qui crée une collision silencieuse. Constat de l'opérateur : "c'est pas un outil clair car il permets de pointer un fichier dans le tree, mais dans une suite par exemple on pourrait avoir plusieurs workdirs qui utilisent le meme shortcut et ça foutrait la merde."

**Audit des usages réels** (fait avant de trancher) :
- Définition : `item_target_directory.py:257` (`get_shortcut`)
- Seulement 2 call sites externes : `_init_registry` du kernel (déjà contourné) et `commands/registry/build.py:19` (commande manuelle `wex registry/build`, trivial à réécrire en path direct)
- Constantes `SHORTCUT_REGISTRY` et `SHORTCUT_LOGS_ERRORS` dans `kernel_workdir.py` — la 2e n'est appelée nulle part
- Surface à supprimer : `set_shortcut`, `get_shortcut`, `get_shortcut_or_fail`, attribut `shortcuts: dict`, exception `UndefinedShortcutException`, clé `"shortcut"` dans les configs YAML/dict

**Décision d'implémentation** : remplacer par un chemin direct construit avec `from wexample_app.const.path import APP_DIR_NAME_TMP` puis `self.get_path() / APP_DIR_NAME_TMP / "registry.json"`. `APP_DIR_NAME_TMP` (wexample_app) et `CORE_DIR_NAME_TMP` (wex-core) valent tous deux `Path("tmp")`, mais `APP_DIR_NAME_TMP` a été choisi car sa couche est plus upstream — à utiliser aussi dans `_init_registry` pour cohérence.
