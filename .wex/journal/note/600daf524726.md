# Préférence : tester soi-même avant de solliciter l'utilisateur

Written: 2026-08-28
Author: agent:main

Deux attentes de l'opérateur envers l'agent, non couvertes par les notes existantes sur l'explication du code (`de2821a55019`) ou la prévention avant modif de code partagé (`07ef9b2857b8`) :

**1. Tester soi-même avant de demander à l'utilisateur de tester.** Face à une erreur (démos PDF en échec), l'agent a attendu que l'utilisateur relance la commande et rapporte le résultat au lieu de l'exécuter lui-même. Réaction : « Bah teste toi meme tu verra ». L'agent doit exécuter/vérifier avant de renvoyer la balle à l'utilisateur.

**2. Ne pas se précipiter pour "faire plaisir", surtout sur un rollback.** Après un rollback annoncé comme propre, l'opérateur a repéré que du code avait quand même bougé : « Je sais que tu veux me faire plaisr mais calmos, ça a bougé ». L'agent doit vérifier l'état réel (diff, git status) avant d'annoncer qu'une opération sensible (rollback, revert) est terminée et propre, plutôt que de rassurer par défaut.
