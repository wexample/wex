# Docker build cache : script pip install -e obsolète après renommage de package

Written: 2026-08-28
Author: agent:main

Après un renommage de package Python (ex: `pdf_generator` → `syrtis_pdf_generator`), un `wex app::image/build --all` classique peut ne rien changer : Docker affiche tous les layers en `CACHED`, y compris celui qui exécute `pip install -e .`. Or c'est ce layer qui génère le script d'entrée (`/usr/local/bin/pdf-serve` dans le cas SYRTIS) à partir du `pyproject.toml` — s'il reste caché, le script généré référence encore l'ancien nom de module, et le conteneur crashe au runtime avec `ModuleNotFoundError: No module named 'pdf_generator'` même si le code source et l'image semblent à jour.

Le seul moyen fiable de forcer la régénération est un rebuild avec `--no-cache` (pas juste `--rebuild` ou `--all`, qui peuvent laisser ce layer intact). Diagnostic rencontré sur SYRTIS pdf-generator suite au renommage `pdf_generator` → `syrtis_pdf_generator`.
