# --rebuild fusionne clear-cache et no-cache build (voulu)

Written: 2026-08-28
Author: agent:main

Dans `app::image/build`, le build docker est désormais toujours en `--no-cache` (le code mort conditionnel a été retiré). Pour `app/start` et `app/restart`, l'option `--clear_cache` a été supprimée au profit d'une seule option `--rebuild` qui déclenche à la fois un `docker build --no-cache --all` et un `docker compose up --build`.

Raison explicite de l'opérateur : "En fait clear cache et rebuild je veux bien qu'il n'y en ait qu'un seul, l'idée c'est que ça bourine pour tout clear quoi" — volontairement une seule option agressive plutôt que deux options fines (l'une pour vider le cache, l'autre pour rebuild), pour éviter la confusion entre les deux comportements proches. Si quelqu'un cherche plus tard une option de rebuild "léger" sans purge totale du cache, elle a été retirée intentionnellement, pas oubliée.
