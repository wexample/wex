# Risque git : agents concurrents sur le même code

Written: 2026-08-27
Author: agent:main

Pendant une session de travail sur l'async de `filestate` (parallélisation de `build_operations`), l'opérateur a signalé avoir lancé un second agent en parallèle sur la même modification, sans le préciser au départ : « j'ai lancé un autre agent en même temps que toi sur cette modif, c'est moi aussi qui ai fais le con, donc il faut faire gaffe si on se sert de git ».

Conséquence pratique : avant tout `git checkout`/rollback destructif quand plusieurs agents peuvent tourner en parallèle sur le même repo, vérifier explicitement l'état non-commité de tous les packages concernés (diff, statut, HEAD) plutôt que de supposer que le diff visible est uniquement le sien — un rollback git peut écraser le travail d'un autre agent en cours si l'opérateur fait tourner plusieurs sessions simultanées sans le signaler à l'avance.
