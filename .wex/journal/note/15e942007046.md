# Patch prompt/screen (request_refresh) laissé en place après abandon

Written: 2026-08-28
Author: agent:main

Complète la note `b0ea204899f7` (abandon du screen de progression pour rectify, retour aux logs).

Durant la tentative d'affichage screen pour la progression multi-thread de `app::state/rectify --dry-run`, une modification additive a été faite dans la lib `prompt`, sur `ScreenPromptResponse` :
- ajout d'un `threading.Event _tick_event`
- ajout d'une méthode publique `request_refresh()` (mode "push" au lieu du seul poll)
- dans `render()`, `sleep(0.05)` remplacé par `self._tick_event.wait(timeout=0.5)` + `clear()`
- ajout d'un `min_refresh_interval` (anti-flicker, type max-FPS, gap minimum entre deux redraws)

Malgré l'abandon complet du screen pour rectify (retour à la version log par-worker), ce patch a été **conservé tel quel** dans la lib `prompt` — décrit par l'agent comme "additif et non-breaking", donc sans risque pour les callers existants. Personne ne l'a explicitement retiré ni commité de façon définitive ; il n'est actuellement appelé par aucun code applicatif. Si on lit `ScreenPromptResponse` aujourd'hui, `request_refresh()` et `min_refresh_interval` semblent être des features prêtes à l'emploi — en réalité ce sont les restes d'une tentative abandonnée, gardés au cas où un futur cas les exploite proprement.

Cause jamais élucidée par ailleurs : l'empilement des lignes "Inspecting" au screen restait inexpliqué ("Je ne sais pas d'où ça vient", après recherche du print fantôme sans succès) — l'agent soupçonnait une interaction ANSI/terminal/IDE hors de son contrôle plutôt qu'un vrai bug du code.
