# Registry : mode singleton comme option standard (idée SharedRegistry)

Written: 2026-08-27
Author: agent:main

Lors de la migration `RunnerRegistry` vers `Registry[T]` (migration #3), le mode singleton statique a été supprimé au motif qu'il n'avait "aucun consommateur externe". L'opérateur a contesté ce point :

> Jamais consommé ? Ah oui vraiment ?
> Le mode singleton pour moi, ce doit être une option valide possible quand même, et standard

Vérification faite : aucun consommateur trouvé dans `/home/weeger/Desktop/`, mais la recherche ne couvre pas d'éventuels projets externes non présents sur la machine, donc la conclusion "jamais consommé" n'est pas garantie.

En réponse, une piste de design a été esquissée mais jamais implémentée ni tranchée : une variante `SharedRegistry[T]` de `Registry[T]`, ajoutant une méthode de classe `shared()` qui expose une instance partagée accessible globalement — pour que le mode singleton devienne un pattern standard du framework Registry plutôt qu'une solution réinventée au cas par cas quand un registre en a besoin.

À trancher si le sujet est repris : faut-il ajouter ce mode à l'architecture Registry (probablement en lien avec les autres travaux de généralisation Registry déjà en cours), ou le mode singleton doit-il rester géré ponctuellement par chaque registre qui en a besoin ?
