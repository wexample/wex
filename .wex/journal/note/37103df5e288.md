# Pool size par défaut passé à 32 (justification technique)

Written: 2026-08-28
Author: agent:main

Complète la note `bdbee395780e` (préférence utilisateur pour un réglage "performance" plutôt que balanced/économique sur la taille du pool de `parallel_map`).

Suite à cette préférence, le défaut de `max_workers` a été changé de 8 à 32, avec la justification suivante :

- 32 correspond au cap par défaut du `ThreadPoolExecutor` de Python lui-même quand `max_workers=None` — c'est le standard "I/O slack" officiel, pas un nombre arbitraire.
- Pour de l'I/O filesystem (cas de `build_operations`/`apply_operations`), 32 workers × ~3 file descriptors ≈ 96 FDs ouverts max, très en dessous de la limite kernel par défaut (1024).
- Pour du code CPU-bound pur en Python, le GIL sérialise de toute façon — augmenter le pool à 32 n'aggrave rien dans ce cas, et profite pleinement dès qu'il y a du blocage I/O (lecture fichier, subprocess, réseau).
