# io.progress() spamme au lieu d'overwrite hors contexte screen

Written: 2026-08-28
Author: agent:main

Complète les notes 9325c73c7ba8 (ThreadPoolExecutor Ctrl+C) et b0ea204899f7 (screen d'avancement abandonné pour les logs).

Lors de la tentative d'ajouter une barre de progression sur `wex app::state/rectify --dry-run` (parallélisation de `build_operations`), l'appel à `self.io.progress(...)` a été utilisé en dehors d'un contexte `screen`/TUI. Résultat observé : au lieu d'overwriter la ligne (comportement attendu d'une barre de progression), chaque update réimprime une nouvelle ligne dans le terminal, ce qui remplit tout le shell de lignes `Inspecting 488 items ... 44%` répétées.

Cause : `io.progress()` a un mode "live update" qui ne fonctionne correctement que dans certains contextes (screen géré), mais reprint bêtement en mode terminal normal. À ne pas réutiliser tel quel pour une progress bar simple en sortie standard — il faut soit rester sur des logs numérotés discrets (`N/488`), soit implémenter un vrai rendu via le mécanisme screen (lui-même abandonné pour ce cas, cf. b0ea204899f7).
