# Diagnostic concret : tests démos PDF cassés par l'injection APP_PROJECT_NAME/APP_PATH

Written: 2026-08-27
Author: agent:main

Complète le todo `c50868327f43` (Yml scripts n'ont pas APP_PROJECT_NAME / APP_PATH injectés) avec un cas de reproduction concret.

Sur le projet SYRTIS, package `pdf-generator`, la commande `wex .pdf/generate-demos` échouait avec 0/13 démos passées, alors que le script `generate_demos.yml` fonctionnait parfaitement lancé à la main avec les mêmes variables.

Cause : le script bash calcule `CONTAINER="${APP_PROJECT_NAME}_pdf_generator"`. Quand wex exécute le script yml, `APP_PROJECT_NAME` n'est pas exporté dans l'environnement bash — `CONTAINER` vaut donc `_pdf_generator` au lieu de `pdf-generator_local_pdf_generator`, et le `docker exec` échoue silencieusement (le script masque l'erreur réelle, affichant juste `[FAIL]` pour chaque démo).

À noter séparément : ce n'était pas un problème du renommage `pdf_generator` → `syrtis_pdf_generator` (déjà tracké par le todo `2a7fee81dbc2` et corrigé pendant cette session) — malgré la correction complète du renommage, les tests échouaient toujours, uniquement à cause de ce bug d'injection de variables. Une fois `c50868327f43` corrigé, il faut relancer `wex .pdf/generate-demos` dans SYRTIS pdf-generator pour confirmer que les 13 démos passent.
