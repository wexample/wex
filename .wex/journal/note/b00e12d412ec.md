# suite/status : pourquoi la parallélisation de la collecte ne bordélise pas l'output

Written: 2026-08-28
Author: agent:main

Crainte soulevée : paralléliser `suite/status` (ou du code similaire type `package__suite__status`) pourrait rendre l'affichage terminal confus (« bordélique »).

Réponse vérifiée : ce n'est pas le cas ici, pour deux raisons combinées :
- dans `status.py`, la boucle sur les packages ne logge rien elle-même — elle se contente de collecter 2 valeurs par package (via 2 appels subprocess git). L'affichage (`context.io.table(...)`) n'est appelé qu'une seule fois, après la boucle complète.
- les appels subprocess git utilisent `inherit_stdio=False` partout, donc ils ne peuvent pas écrire directement dans le terminal.

Conséquence : on peut paralléliser la phase de collecte (les appels git) sans risque de sortie mélangée, car l'affichage reste strictement séquentiel et se produit après coup. Ce pattern (collecte async + affichage unique en fin de boucle) est le critère à vérifier avant de paralléliser n'importe quelle boucle similaire ailleurs dans le projet : si la boucle logge au fil de l'eau, le risque de sortie confuse existe ; si elle ne fait que collecter puis afficher après coup avec des sous-process en `inherit_stdio=False`, la parallélisation est sûre côté output.
