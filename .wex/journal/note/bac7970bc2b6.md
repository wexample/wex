# Pourquoi le knowledge n'est pas généralisé inter-packages (cascade multi-niveaux)

Written: 2026-08-27
Author: agent:main

Décision (roadmap : passé en « Dropped ») : ne pas donner au knowledge (contrairement au README) le droit de lookup multi-niveaux (package → addon langage → addon app → suites parentes).

Raisonnement qui a mené à ce choix, pas visible dans le code :

- L'exemple qui semblait justifier la généralisation — une page « style de code » commune à tous les packages — n'en est en fait jamais un bon candidat : le style de code est déjà géré par le hook `PreToolUse` du formatter, donc il n'a jamais eu besoin d'exister comme page de knowledge lue par les agents.
- Le vrai coût d'une page héritée n'est pas le lookup lui-même, c'est ce qu'il déclenche en aval : la page se matérialise dans `built/en` **et** `built/fr` de chaque package qui en hérite, se fait traduire une fois par package (l'engram est indexé par workdir, le traducteur n'a aucun moyen de savoir que deux copies sont le même texte), et se retrouve committée en autant d'exemplaires que de packages.
- Le besoin réel derrière l'idée était l'adressage (pouvoir référencer un savoir depuis plusieurs packages), pas la duplication de contenu — et la phase 6 (roadmap) traite déjà cet adressage autrement.

Citation de l'opérateur, tranchant explicitement : « Oui ou tu la vire, h'ésite pas a simplifier / drop les trucs passés » et « A court terme, j'en ai pas besoin. »

À retenir si le sujet revient : ne pas réintroduire une cascade multi-niveaux pour le knowledge sans d'abord résoudre le problème de traduction dupliquée par engram-indexé-par-workdir.
