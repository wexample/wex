# Règle : pas de concept app dans core, storage opaque à la place

Written: 2026-08-27
Author: agent:main

Principe de conception dégagé lors d'un désaccord sur `CommandMethodWrapper` (core) : un besoin propre à un addon (ici `config_requirements`, une vérification de config utilisée par l'addon app) ne doit jamais devenir un champ nommé dans une classe core, même quand c'est la solution la plus directe.

La solution retenue quand core doit porter une donnée pour un addon : un champ générique et opaque type `extra: dict` (clé/valeur libre), que l'addon remplit et relit avec ses propres clés. Core n'a aucune connaissance du contenu ; il fournit juste le stockage. Alternative écartée : poser l'attribut directement sur l'objet fonction Python (attributs arbitraires autorisés) — fonctionnellement correct mais jugé "un peu moche" et moins découvrable.

À appliquer par analogie chaque fois qu'un addon veut attacher des données spécifiques à un objet core (wrapper de commande, etc.) plutôt que d'étendre le core avec des champs dédiés à un seul addon.
