# Éditable partiel : TypeError configure= trahit wex_core resté en copy

Written: 2026-08-27
Author: agent:main

Complète le todo `e7a8233089b1` (editable cassé si `app::setup/install` lancé au niveau package plutôt que suite).

Symptôme observé en plus du problème déjà connu : quand l'install editable s'interrompt en cours de route (ex: crash sur un `.pdm-build` root-owned pendant l'install package par package), certains packages de la suite finissent editable et d'autres restent en copie (wheel figée). Si `wex_core` reste en copie pendant que `filestate` local a déjà évolué, ça produit une erreur qui n'a l'air de rien à voir avec l'install :

```
TypeError: Kernel._create_workdir_state_manager() got an unexpected keyword argument 'configure'
```

Ce n'est pas un bug de filestate ni de kernel : c'est un mismatch de version entre le code local (qui passe déjà `configure=`) et l'ancien `wex_core` figé en wheel/copie (signature sans `configure=`). Le fix est de réinstaller spécifiquement `wex_core` en editable — pas besoin de tout relancer.

Utile pour diagnostiquer rapidement une prochaine occurrence : un `TypeError` sur un kwarg qui existe pourtant dans le code source local signale presque toujours qu'un package de la chaîne d'imports est resté en copie au lieu d'editable.
