# Fichiers markdown obligatoires par niveau — décision anti-pourrissement

Written: 2026-08-27
Author: agent:main

Décision prise pour automatiser la doc sur les 89 dépôts de packages maintenus, sans liste de noms en dur en Python et sans imposer le même fichier partout.

Principe retenu : n'est obligatoire **dans le dépôt lui-même** que ce que personne d'autre ne peut écrire à sa place. Tout ce qui est générique (install, tests, licence, signature) reste dans l'addon ou la suite et descend par la cascade des contrats — zéro fichier local à dupliquer.

Au niveau *toutes app* (`ManagedWorkdir`), deux fichiers rendus obligatoires :
- `usage/overview.md.j2` — ce que fait le projet ; c'est l'intro du README, qui ne venait avant que de `global.description` (une ligne), jugé insuffisant.
- `contributing/architecture.md.j2` — comment le projet est fait ; le document qu'un agent doit lire avant de toucher au code.

Ces fichiers sont créés par `rectify` mais restent des stubs : le fichier contient un commentaire Jinja qui énonce la consigne, le contenu réel n'est pas rédigé automatiquement — le README continue d'afficher la `description` de `config.yml` tant que le stub n'est pas rempli. Le remplissage est une étape séparée, confiée à un agent `author` disposant du contrat.

Pour le composeur de README partagé entre les 89 packages : un seul `_content.md.j2` posé dans `package-readme/` au niveau de la suite (pas dans chaque dépôt) — `_composer_exists()` balaie ce niveau, donc tous les packages en héritent sans fichier local, et on ne modifie qu'un seul fichier le jour où l'ordre des sections change.

Mécanisme identifié en aparté (à traiter ailleurs) : filestate peut déjà s'appuyer sur un agent pour rédiger le contenu d'un fichier — c'est ce mécanisme qui devra remplir les stubs `overview.md.j2` / `architecture.md.j2` générés par rectify.
