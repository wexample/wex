# Doc wex : usage/commands, contrats, corrections

Written: 2026-08-27
Author: agent:main

Travail terminé sur la documentation de wex (README + knowledge), en plusieurs étapes :

**usage/commands.md.j2** créé en anglais, rendu dans le README juste après `Addons` : les quatre formes de commande (`addon::group/command`, `.group/command`, `~group/command`, `@service::group/command`), `--help` par commande, les options noyau (`--quiet`, `-vvv`, `--output-*`), et `core::command/create`, chaque exemple exécuté avant d'être écrit dans la doc.

Deux bugs trouvés et corrigés en écrivant cette doc :
- `wex --help` plantait, alors que le message d'erreur de `wex` sans argument le recommande.
- `core::info/show` renvoyait un `UNEXPECTED_ERROR`.

**Titres corrigés** : `output`, `venv`, `vision`, `environment-variables`, `webhooks` commençaient en `#` au lieu de `##` ; tous les sous-titres décalés d'un cran, les commentaires shell dans les blocs de code laissés intacts.

**Contrats de documentation créés** (douze au total, validés via `discover_contracts()` : chaque cible existe, chaque `sources:` pointe sur un fichier réel). En les rédigeant, trois dérives trouvées et corrigées :
- `testing.md.j2` citait une commande `test::run/all` inexistante (la vraie est `app::test/run`) et une arborescence annonçant `integration/` et `conftest.py` qui n'existent pas.
- `venv.md.j2` parlait encore de `wex-6/` et d'un `app_manager` dont le contenu ne correspond plus à ce qui est décrit.
- `output.md.j2` listait des flags `--v/--vv/--vvv` que le noyau n'expose pas sous cette forme.
- `environment-variables.md.j2` citait des numéros de ligne pointant dans `wexample-wex-core`, paquet absent de ce dépôt.

Bug de plomberie trouvé et corrigé : le contrat `installation` avait un `formatter` vide — c'était le seul fichier de doc dont les agents ne recevaient pas les règles d'écriture `app-doc`. Les douze contrats portent maintenant un `formatter`.

**environment-variables.md.j2 déplacé** de `usage/` vers `contributing/` (il décrit des mécanismes internes, pas quelque chose qu'un utilisateur touche), avec son contrat et son engram déplacés en même temps dans le même mouvement — la clé d'un engram étant son chemin, en oublier un revient à perdre l'engram. Le README n'a pas changé, ce document n'y figurait pas.

Nettoyage annexe : neuf fichiers `.lock` orphelins supprimés dans l'arbre des engrams — vides, non suivis par git, ciblant des `.md` renommés depuis en `.md.j2`.
