# Pourquoi KernelRegistry avant les autres options (complète e3a174b669f8)

Written: 2026-08-28
Author: agent:main

Complète le todo `e3a174b669f8` (Prochaine priorité registrification : KernelRegistry → DiskPersistedRegistry) avec le raisonnement qui a motivé ce choix plutôt que les deux alternatives envisagées :

- **Async `_create_options` (perf)** — écarté en premier : refacto profonde dans `wexample_config`, risque de toucher beaucoup de code sans avoir encore validé la 4e variante du framework de registres.
- **#4 EventDispatcher** — écarté en premier : le plus complexe des trois (priorité, thread-safety, registration dynamique…), à traiter après.
- **KernelRegistry → DiskPersistedRegistry** — choisi : c'est la seule variante du framework définie mais jamais exercée, et c'est le registre le plus central de wex (l'index des 111 commandes), donc la validation la plus significative.
