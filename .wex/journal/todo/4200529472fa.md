# Supprimer get_shortcut (registre workdir)

Opened: 2026-08-27
Updated: 2026-08-27
Author: agent:main

Décision prise pendant la session : supprimer le mécanisme `get_shortcut`/`set_shortcut`/`get_shortcut_or_fail` d'`item_target_directory.py:257`, jugé mort fonctionnellement et bogué par design.

Raison : dans une suite, plusieurs workdirs peuvent porter le même shortcut, ce qui provoque une collision de noms — c'est un problème identifié et déjà abandonné auparavant, pas juste une question de style.

État des lieux relevé (à revérifier avant de reprendre, le code a pu bouger) :
- Définition : `item_target_directory.py:257`
- 2 call sites externes seulement : `_init_registry` (kernel, déjà contourné) et `commands/registry/build.py:19` (`wex registry/build`)
- Usage interne probable en `item_target_directory.py:265`
- Constantes `SHORTCUT_REGISTRY` et `SHORTCUT_LOGS_ERRORS` dans `kernel_workdir.py` — la seconde n'est appelée nulle part
- Attribut `shortcuts: dict`, exception `UndefinedShortcutException`, clé `"shortcut"` dans les configs YAML/dict — toute cette surface à retirer

À faire :
1. Réécrire `commands/registry/build.py:19` en accès direct au chemin du registre, sur le modèle de `_init_registry` :
   ```python
   from wexample_app.const.path import APP_DIR_NAME_TMP
   ... = self.get_path() / APP_DIR_NAME_TMP / "registry.json"
   ```
   `APP_DIR_NAME_TMP` (wexample_app) a été choisi plutôt que `CORE_DIR_NAME_TMP` (wex-core) — même valeur `Path("tmp")`, mais couche plus upstream.
2. Supprimer `get_shortcut`, `set_shortcut`, `get_shortcut_or_fail`, l'attribut `shortcuts`, l'exception `UndefinedShortcutException`, la clé `"shortcut"` des configs, et les constantes `SHORTCUT_REGISTRY`/`SHORTCUT_LOGS_ERRORS` si effectivement inutilisées.
