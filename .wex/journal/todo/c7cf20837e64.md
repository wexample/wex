# Option --type pour app/init (choix classe workdir)

Opened: 2026-08-27
Updated: 2026-08-27
Author: agent:main

`app/init` génère aujourd'hui un app générique : `AppAddonManager.create_app_workdir()` cherche une classe `AppWorkdir` dans `<app>/.wex/python/app_manager/app_workdir.py` (via `module_load_class_from_file`) et retombe sur `ManagedWorkdir` si le fichier est absent. `app/init` n'écrit jamais ce fichier. Or il suffit d'une classe de 5 lignes (ex. `class AppWorkdir(PythonPackageWorkdir): ...`) pour que `state/rectify` génère tout le squelette du package (pyproject complet, AGENTS.md, CLAUDE.md, .wex/ai/*, src/<vendor>_<name>/{__init__.py,py.typed}, tests, README, etc.).

Demande : ajouter une option `--type` à `wex app::app/init` pour choisir la classe de workdir à écrire dans `.wex/python/app_manager/app_workdir.py`, au lieu de laisser l'app générique.

Fichier cible : `wex-addon-app/src/wexample_wex_addon_app/commands/app/init.py` (le path exact dépend de l'emplacement du dépôt, ex. `/home/weeger/Desktop/WIP/WEB/WEXAMPLE/PACKAGES/PYTHON/wex/wex-addon-app`).

Questions ouvertes à trancher avant d'implémenter :
- Où vivent les templates par type ? Chaque addon devrait posséder sa propre classe plutôt qu'une table codée en dur dans wex-addon-app.
- Comment les types sont-ils découverts/listés, pour que `--type` valide la valeur et que `--help` les énumère ?
- La classe générée doit-elle rester vide ou porter des conventions ?
- `--type` doit-il aussi renseigner `global.type` dans `.wex/config.yml` (actuellement codé en dur à `"app"` par `app/init`) ?
