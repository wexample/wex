# Registrification : implémenter Protocol Registrable + hiérarchie Registry

Opened: 2026-08-27
Updated: 2026-08-27
Author: agent:main

Suite à l'audit registrification (roadmap `.wex/knowledge/roadmap/todo/registrification.md`, Phase 1 faite : 7 candidats identifiés, 3 STANDARD, 2 cas spéciaux, 4 faux positifs), le design de la Phase 2 a été validé en conversation mais pas encore implémenté (ni forcément reporté dans le fichier roadmap) :

**Décision : 3 variantes de `Registry`, en hiérarchie**
| Variante | Stocke | Init managée ? | Cas d'usage | Exemple |
|---|---|---|---|---|
| `Registry[T]` (base) | dict<key, T> — instances ou classes | Non, juste lookup | Dictionnaires statiques | OptionClasses, lookup pur |
| `SingletonRegistry[T]` (hérite Registry) | classes uniquement, instance maintenue par le Registry | Oui, `init_all_sync/async()` + dépendances topologiques | Classes à instancier une fois, vivantes | AddonManager, Middleware, ScriptRunner, StepGuard |
| `DiskPersistedRegistry(Registry)` | idem + persistance disque | paramétrée par un `StructuredFile` (YAML/JSON) en argument | Registres sauvegardés sur disque | `KernelRegistry` (commands, JSON), futurs caches YAML |

Autres décisions actées à valider/appliquer à l'implémentation :
- Utiliser un `Protocol Registrable` par défaut (pas un Mixin) ; si le Protocol s'avère trop contraignant sur un cas concret, basculer ce cas en Mixin (garde-fou, pas un principe absolu).
- `[T]` est du typing générique Python pur (comme `list[int]`), orthogonal à la décoration `@base_class` que `Registry` garde par ailleurs.
- Pas de rétrocompatibilité à préserver : corriger tous les appelants en une fois plutôt que patcher progressivement.
- `aiofiles` vs `asyncio.to_thread` : trancher au premier cas concret rencontré, pas de règle a priori.
- `@async` au niveau CLI des commandes : explicitement reporté à plus tard (hors scope immédiat).

La conversation s'arrête sur le "vas y" de l'opérateur donnant le feu vert à l'implémentation du Protocol `Registrable` ; rien dans la suite de la session ne confirme que cette implémentation a été faite.
