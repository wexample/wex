# Yml scripts n'ont pas APP_PROJECT_NAME / APP_PATH injectés

Opened: 2026-08-27
Updated: 2026-08-27
Author: agent:main

En diagnostiquant un bug (container docker exec qui échoue silencieusement dans un script bash défini par un `.wex/commands/.../*.yml` custom), on a découvert que le script, lancé via wex, construit un nom de conteneur faux (`_pdf_generator` au lieu de `pdf-generator_local_pdf_generator`) car les variables d'environnement `APP_PROJECT_NAME` et `APP_PATH` ne sont pas exposées dans le shell bash du script yml. Lancé à la main avec ces variables positionnées, le script fonctionne parfaitement.

À vérifier/faire :
- Existe-t-il déjà un mécanisme wex pour injecter ces variables (ou équivalentes) dans l'environnement des scripts bash définis en yml ? Si oui, pourquoi n'est-il pas actif ici et comment le déclencher ?
- Sinon, l'implémenter (ou documenter l'alternative officielle : lire `docker.env`, utiliser un nom de conteneur fixe/dérivé autrement) pour que les scripts custom puissent construire le bon nom de conteneur sans deviner.
- Le symptôme est un échec silencieux du `docker exec` (pas d'erreur claire), donc en profiter pour vérifier si l'échec pourrait aussi être surfacé plus clairement.
