# Roadmap : Réorganisation de la documentation

Opened: 2026-08-19
Updated: 2026-08-27

**Single place for this work.** Everything related to the documentation system is managed
here.

Starting problem: very little documentation had been written and the author was lost in it.
The goal is a single convention applied everywhere, and documentation maintained as
automatically as possible from the code.

---

## Principles

1. **Single source of truth** — a piece of information exists in one place only. The rest
   is generated, imported or referenced.
2. **Generation > manual writing** — what can be produced by template must be.
3. **wex as the primary interface** — agents explore through wex commands; the knowledge is
   the human-readable cache for those without access.
4. **Convention over configuration** — same structure everywhere; variants are additions,
   not exceptions.
5. **`knowledge/` = timeless, `journal/` = dated.**

## Structure of `.wex/knowledge/`

```
knowledge/
├── readme/          # .md.j2 fragments → generated README
├── usage/           # using the project without modifying it
├── cookbook/        # one recipe per file, added as the need shows up
├── contributing/    # modifying / extending it (humans + agents)
├── specifications/  # lasting reference (vision, constraints, contracts)
└── built/<lang>/    # all of the above, rendered standalone and committed
```

At suite level, `package-readme/` is added — fragments inherited by child packages.

---

## Where it stands

Done, at scale, for Python: the 37 packages each have a rebuilt README, the three mandatory
pages written, and `built/en/` plus `built/fr/` committed. Of the three axes — writing it,
fixing it, reading it — the first two are closed.

Reading it has four working surfaces: the generated README, the built pages in two
languages, stack-wide search (`app::knowledge/search`), and the same search exposed as an
agent tool.

## What is left

- **`app::sources/search|grep`** — the sibling family for the code. An agent that cannot
  find the documentation falls back to the sources, and has no suite-wide way to read them.
- **`AGENTS.md` (case B)** — last, since it can only stop pointing at dead ends once there
  are commands and an artefact to point at instead. Its two current branches both lead
  nowhere: `ai::agent/talk` is a human surface, and "browse `.wex/knowledge/`" points at
  Jinja sources.
- **Agent prompts** — define their composition (fragments + context compiled on the fly:
  project structure, dependencies, available commands), reusing the documentation's own
  aggregation building block. Pick up the tag taxonomy (`suite@99e98dd`) for MCP filtering.
- **Non-Python repositories** — once their language addons ship the templates the Python
  one has. Migration `6.0.133-1` renames their remaining `.md` pages to `.md.j2`; the ones
  carrying Jinja delimiters as prose are reported and left for a human.

## Decisions that still bind

- **No index for search.** 150 pages, 7 000 lines: a live grep crosses them in a blink, an
  index would be a second thing to keep fresh.
- **Search answers at the page level**, not line by line — the median built page is 40
  lines, so a broad query answered line by line costs more to read than the pages it points
  at. `--lines` gives the grep form.
- **The asking app's pages come first**, whatever the scope.
- **No knowledge page inherited through the 4-level cascade.** It would materialise, be
  translated and be committed once per package. The need was addressing, not duplication,
  and search answers it.
- **`app::knowledge/read` stays the reader of *service* knowledge.** For an app's own pages,
  `built/<lang>/` already puts the text in a flat file anyone can open.
- **Exported `.md` files are versioned generated artefacts**, committed like the README: a
  reader who clones without wex has nothing else.
- **Code rules live in formatters**, delivered by a `PreToolUse` hook to whichever agent is
  about to edit a matching file. Design rules are pulled earlier, through
  `ai::design/rules`.
- **Per-file rules live in contracts** next to the file they govern
  (`.wex/ai/contracts/<mirrored path>.contract.yml`), with an `instructions` block per agent
  and `sources:` acting as change triggers.
- **`path()` fails the build** rather than let a moved file rot silently.

---

## Leads to investigate (not decided)

- **Generate documentation from the code.** First candidate: a document describing the
  `.wex/` tree, since `managed_workdir.prepare_value()` is the source of truth. Second: the
  command inventory.
- **One agent per documentation file**, responsible for keeping it current.
- **Link code and documentation**: watch diffs, or tag comments. Implies update lifecycles.
- **Reproducible standard**: check applicability outside the Python ecosystem (syrtis,
  PHP/JS packages).
